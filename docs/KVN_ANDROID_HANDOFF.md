## Как перенести исходный проект в GitHub
1. В другом чате/на компьютере получить **последний** `KVN-Android-v0.1.2-test-source.zip`, распаковать каталог `KVN-Android-Starter`. Не использовать APK как замену исходникам.
2. В репозитории `gwz-tools/config-hub` создать ветку `feature/kvn-android-012` от `main`.
3. Загрузить **содержимое** распакованного каталога в `android/kvn/`: `settings.gradle.kts`, `build.gradle.kts`, `gradlew`, `gradle/wrapper/**`, `app/**`, `README.md`, `CHANGELOG.md`, `scripts/check_assets.py`, `docs/**`. Папка должна содержать `android/kvn/settings.gradle.kts` — **не** `android/kvn/KVN-Android-Starter/settings.gradle.kts`.
4. Рабочий CI уже добавлен в репозиторий: `.github/workflows/kvn-android-ci.yml`; не переписывать его без необходимости.
5. **Не загружать** APK, `.jks`, `debug.keystore`, `local.properties`, `.gradle/`, `**/build/`, пользовательские конфиги и приватные подписки в публичный репозиторий.
6. Открыть PR на `main`, дождаться реального успешного job **KVN Android CI**: `assembleDebug`, `testDebugUnitTest`, `lintDebug`, `scripts/check_assets.py`. Если красный — читать лог и чинить конкретную ошибку. После исправления и успешной сборки объединить PR.

## Как скачать готовую APK
1. Открыть `gwz-tools/config-hub` → **Actions** → **KVN Android CI** → последний успешный запуск по нужному commit SHA.
2. В разделе **Artifacts** скачать `kvn-android-debug-<номер>` (это ZIP). Внутри `app-debug.apk` и `app-debug.apk.sha256`.
3. Проверить SHA-256 полученной APK с приложенным файлом. Установить её на Android 8+ и проверить интерфейс и обновления. Ссылка на тестовый artifact может требовать авторизацию и обычно хранится 30 дней.
4. Для долговременной публичной ссылки на APK нужна **GitHub Release** с отдельной стабильной подписью; нельзя считать debug artifacts системой обновления пользователей.

## Ключ подписи: важный блокер обновлений
Встроенная debug-подпись GitHub Actions скорее всего **отличается** от debug-подписи установленной 0.1.1, потому что ephemeral runner генерирует новый ключ. Такое обновление поверх установленного приложения Android отклонит (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`), даже если `applicationId` совпадает. Для теста можно удалить старую debug-версию (локальные данные будут потеряны), либо подписывать новым CI APK **тем же сохранённым тестовым ключом** из секретного хранилища. *Никогда не публиковать ключи и пароли в GitHub*. Для пользователей нужен отдельный release-ключ с управляемой ротацией.

## Цикл последующих доработок
1. Всегда сверить текущие `main`, последний commit SHA, открытые PR и Android CI, перед изменениями читать реальные исходники из `android/kvn/`.
2. Создать новую ветку от свежей `main`; менять код **точечно**, без пересоздания проекта.
3. Повысить `versionCode`, обновить `versionName` и `CHANGELOG.md`; не изменять `applicationId` и имя приложения.
4. PR → GitHub Actions → успешные тесты → Artifacts с APK → установка на реальном телефоне → фиксация результатов и merge.
5. Репозиторий приложения не должен менять без отдельного решения `fast.txt`, `cloud-vless.txt`, `routing-feed`, источник подписок, правила роутеров, OpenWrt и Cloudflare.
6. **Не менять** `app-release.json` в `main` до фактического публикации нового подписанного APK и работоспособной страницы Release. Установку обновлений Android подтверждает пользователь.
